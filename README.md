# AutoRelink

GRANBLUE FANTASY: Relink のリザルト画面を自動で進め、「再挑戦」を自動選択して
周回を続けるための Python ツールです。GUI アプリ (`app.py`) 1つで、テンプレート
作成（キャリブレーション）と自動実行の両方を行います。

検出する画面と動作:

- 「次へ」の表示を検出 → 決定キー（既定 `Enter`）を押して次に進める
- 「③ 再挑戦する」（未選択）の表示を検出 → `3` キーを押して再挑戦を選択
  （すでに「再挑戦をキャンセル」＝選択済みの場合は何もしない）
- 「リザルトの確認を完了しますか？」のポップアップを検出 → 決定キーを押す
  （「はい」がデフォルトで選択されているため、これで確定する）
- 「引き続きこのクエストに挑戦しますか？」の継続確認ポップアップ（一定回数
  ごとに表示、「いいえ」がデフォルト選択）を検出 → 上移動キー（既定 `W`）
  →決定キーの順に押して「はい」を選択する

このゲームのリザルト画面はマウスクリックではなくキーボード（コントローラー
の決定ボタン相当）でのみ反応するため、すべてキー入力で操作します
（詳細は下記トラブルシューティング参照）。

## 注意事項

- 本ツールはメモリ改ざんや通信改変を行わず、通常のマウス/キーボード入力を
  OS レベルでゲームに送るだけの「連打・周回補助マクロ」です。ただし、
  ゲームの利用規約でマクロ/自動化ツールの使用を禁止している場合があります。
  利用は自己責任で、必ず対象タイトルの利用規約を確認してください。
- オンライン協力プレイ中の使用は他プレイヤーに影響する可能性があるため、
  ソロ/オフライン周回での利用を推奨します。
- 誤動作時にすぐ止められるよう、必ず一時停止/終了ホットキーを覚えておいてください。

## セットアップ

```bash
pip install -r requirements.txt
```

Windows で `keyboard` パッケージがグローバルホットキーを掴むため、
管理者権限のターミナルで実行することを推奨します。

## 起動

```bash
python app.py
```

GUI が起動します。上部のタブで「テンプレート作成」「実行」「設定」を切り替えます。

### 1. テンプレート作成タブ

4つの項目（① 次へ表示 / ② 再挑戦する未選択 / ③ 確認ポップアップのはい /
④ 継続確認ポップアップ）ごとに「キャプチャ開始」ボタンがあります。

1. ボタンを押す
2. ゲーム画面をフォーカスし、対象の画面を実際に表示させる
3. `F9`（設定タブで変更可）を押す → スクリーンショットが撮影される
4. 表示された選択ウィンドウでドラッグして範囲を選び、`Enter` で確定
   （`C` でキャンセル）

この範囲は「その画面が表示されているかどうかの判定」にのみ使われ、実際の
操作はキー入力（範囲の座標に依存しない）なので、範囲の位置や広さは動作に
影響しません。他の画面と紛らわしくない、特徴的な部分を選べば十分です。

保存されたテンプレートはサムネイルで確認できます。解像度やUIスケールは環境
ごとに異なるため、必ず自分の画面から作成してください。

### 2. 実行タブ

- 「開始」で自動化ループを開始（テンプレート未作成の項目があれば警告）
- 「一時停止」/「再開」、「停止」で制御
- ログ欄に検出・操作の履歴が表示されます
- グローバルホットキー: `F8` 一時停止/再開、`F10` 停止
  （ゲーム画面をフォーカスしたままでも効きます）

自動実行中はクリック/キー入力の直前に、AutoRelink がゲームウィンドウを
自動的にフォアグラウンドへ切り替えます（GUI にフォーカスがあっても問題
ありません）。ただし後述の「排他フルスクリーン」の場合はこれだけでは
解決しないので必ず表示モードを確認してください。

### 3. 設定タブ

- `match_threshold`: テンプレート一致のしきい値（0〜1）。誤検出が多い場合は
  上げる、検出しない場合は下げる。
- `poll_interval`: 画面を確認する間隔（秒）。
- `post_key_delay` / `post_click_delay`: 入力後、次の判定までの待機時間。
  画面遷移アニメーションより短いと誤爆するので、体感に合わせて調整。
- `monitor_index`: マルチモニタ環境でゲームが表示されているモニタ番号。
- `pause_hotkey` / `stop_hotkey` / `capture_hotkey`: ホットキーの変更。
- `game_window_title`: キー入力の前に自動フォーカスするゲームウィンドウの
  タイトル（部分一致）。「ウィンドウ確認」ボタンで実際に何が検出される
  か確認できます。
- `confirm_key`: 「次へ」「はい」の代わりに押すキー（既定 `enter`）。
  ゲーム側の決定キー割り当てが異なる場合はここを変更してください
  （例: `space`）。
- `select_up_key`: 継続確認ポップアップで「いいえ」から「はい」に選択を
  移すためのキー（既定 `w`）。ゲーム側の上移動キー割り当てが異なる場合は
  変更してください（例: `up`）。

設定は `config.json` に保存され、次回起動時にも引き継がれます。

## トラブルシューティング

### 「次へ」などは検出（スコア表示）されるのに画面が進まない

検証の結果、このゲームのリザルト/メニュー画面は**マウスの合成クリックには
反応しない**ことが分かっています（ボーダーレスウィンドウでも、ウィンドウを
正しくフォーカスしても、クリックだけは効果がありませんでした）。一方で
**キーボード入力（Escape で「戻る」など）は正常にゲームへ届く**ことを
確認済みです。そのため本ツールはクリックではなく `confirm_key`（既定
`Enter`）のキー入力で「次へ」「はい」を操作します。

それでも進まない場合に確認すること:

1. ゲーム側のキー設定で「決定」に割り当てられているキーを確認し、
   `Enter` と異なる場合は設定タブの `confirm_key` をそのキーに変更する
   （例: `space`）。
2. 設定タブの「ウィンドウ確認」で正しいウィンドウ（`game_window_title`
   に一致するもの）が検出されているか確認する。
3. ゲームの表示モードが排他フルスクリーンの場合はボーダーレスウィンドウ/
   ウィンドウモードに変更する（排他フルスクリーンだとキー入力も届かない
   ケースがあります）。

### 特定のテンプレートだけ検出されない（スコアがしきい値未満）

実行タブの「スコア確認」ボタンを使うと、現在の画面に対する各テンプレートの
一致スコアを実際にクリック/キー入力せずにログへ表示できます。**必ず判定
したい画面（例: 「③ 再挑戦する」が未選択で表示されている画面）を実際に
表示させたまま**このボタンを押してください（違う画面で押すとスコアが
低く出るのは正常です）。それでもスコアが `match_threshold` を大きく
下回る場合は、テンプレート作成タブから該当項目を撮り直してください
（範囲が広すぎる、対象の状態と違うものを撮った、等が典型的な原因です）。
